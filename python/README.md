# cmdop (Python)

Your machines' tools from a program: the same tools agents use through MCP, typed from Rust.

```python
import cmdop

with cmdop.connect() as c:                 # CMDOP_TOKEN, CMDOP_URL
    box = c.machine("box")
    print(box.run("uptime").stdout)
    run = box.stream("make test")
    for piece in run:
        print(piece.data, end="")
    print(run.result.exit_code)
```

Every tool is a typed method on a machine (`box.fs_read(path=...)`), also under its group (`box.fs.read(path=...)`);
`box.screenshot()` decodes the picture. The tools the server answers itself are methods of the client, with no
machine: `c.machines_list()`, `c.tasks_list()`, `c.history_search(text=...)`, `c.docs_read(path=...)` (the docs,
contents first) and `c.showtime_guide(language=...)`,
the guide for a short live demo of what your machines can do. A machine also lets you ask the AI agent programs
installed on it (Claude Code, Codex), the same way for each: `box.agent.list()`, `box.agent.prompt(prompt=...,
session=...)` (the answer and a `session` to continue), `box.agent.sessions()` and `box.agent.cancel(task=...)`; the
agents answer in words or read files, never run commands. `cmdop.connect_async()` is the same, awaited. `src/cmdop/generated/` is generated by `make sdk-generate`; never edit it.

## The same tools over MCP

CMDOP is an MCP server too: an agent reaches these tools at `$CMDOP_URL/mcp` (streamable HTTP) with an agent token
as `Authorization: Bearer`, the same kind of token this package takes, under the same grant and record. The
command or settings for each client: https://docs.cmdop.ai/guides/connect
